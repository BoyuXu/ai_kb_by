# 大肥鱼知识维护规范

生效：2026-11-08。目标是可检索、能解释、可追溯的个人技术知识库。

## 内容去向

- 搜索、广告、推荐：沿用 `rec-search-ads/` 的域与阶段结构。
- 大模型训练、推理、RAG、Agent：归入 `llm-agent/`；主题导航见 `llm-agent/README.md`。
- 日期发现记录是线索，长期知识以主题为主；日报不替代主题整合。
- 本地工具配置与个人环境优化另存本地工作流知识库；金融材料另存金融知识库。

## 每条知识卡必备

问题；三条以内核心结论；来源名称、作者、链接、发布日期或版本、核验日期；阅读覆盖（摘要/正文/视频第几P/字幕/画面）；证据类型（官方事实/作者主张/我们的推断）；适用条件、反例或未解决问题；关联旧笔记；对旧结论的新增、修正或冲突。

## 入库流程

1. 按 UID、BV+分P、论文ID或规范URL去重。历史补课与新内容分别排队，避免新视频一直挤掉旧视频。
2. 视频展开全部分P，读字幕或转写。缺正文留待补，图示/代码/回测表不可由字幕臆测。
3. 对关键技术主张核查官方文档、论文或代码版本。只读摘要的论文明确写“摘要初读”，不报告未读实验细节。
4. 搜索现有同题笔记，优先追加纠错、版本差异和证据。冲突保留双方出处与适用条件。
5. 检查链接、路径、日期与数字；只提交提炼笔记，不上传完整字幕、付费课程原文、凭据或私人日志。
6. 使用独立分支与可审阅 PR 交付，摘要说明新认识、改动文件、覆盖率和未完成项。每次更新保留来源。

## 长期补齐顺序

先修复主题入口与出处，再补 Agent 的工具/上下文/评估，随后训练、推理与 RAG。旧目录的重复文件暂保留；确认引用关系和差异后再做迁移。
