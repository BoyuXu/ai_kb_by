# Agent Harness：模型以外还应验证什么

核验日期：2026-11-08。阅读层级明确分开：官方工程文章相关章节已读；新论文仅摘要初读，未复现实验。

## 新研究线索：复杂组件不必然更好

[Hu 等，Beyond the Model（2026-09-26，arXiv:2609.32459v1）](https://arxiv.org/abs/2609.32459v1) 对不同模型、任务和 Harness 组件进行比较。摘要报告，效果依赖模型能力与任务；某些结构化工具和专用组件有益，压缩或通用子代理在部分任务中可能产生负效应。这是作者在其实验范围内的结论，不足以推广为所有 Agent 的设计定律。

待读正文：任务划分、预算控制、重复试验、代码快照、组件消融和失败案例。摘要数字暂不作为选型依据。

## 官方工程经验：分离可恢复状态

Anthropic 将 session 事件记录、执行循环和执行环境分开，降低某个执行环境故障导致整个任务丢失的风险。这里可迁移的是边界设计，不能据此声称本地部署具有同等可靠性。[Scaling Managed Agents，2026-04-08](https://www.anthropic.com/research/managed-agents)

## 验收必须看最终产物

“模型说完成”与环境里确实形成结果是两件事。Agent 评估应检查任务执行后状态，而不只读最终答复。[Demystifying evals，2026-01-09](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)

本库维护的验收建议（本次工程推断）：

1. 运行层：进程退出码与结构化完成/失败事件；不要用日志中任意出现的401/403判定认证失败。
2. 内容层：正文获取范围、来源、未核验主张与笔记是否存在。
3. 交付层：文件哈希、实际提交及可打开的 PR。完成生成不等于完成发布。
4. 恢复层：任务去重键与已完成阶段落盘，失败后从缺失阶段继续。

关联：[Agent失败模式与解法](Agent失败模式与解法.md)。这套建议首先适用于知识整理流程，性能收益仍需自身任务的测量。

## 四种循环：触发、执行、验收与改进

完整阅读 [Agent智能体深度研究院，2026-07-05，BV1tUMA61ES1](https://www.bilibili.com/video/BV1tUMA61ES1) P1的307段字幕，未逐帧核对。对照 [LangChain，The art of loop engineering，Sydney Runkle，2026-06-16](https://www.langchain.com/blog/the-art-of-loop-engineering) 正文相关章节：agent loop执行动作，verification loop检查结果，event loop决定何时触发，hill-climbing loop利用轨迹调整Harness。它是该文的工程分类，不是全行业强制四层标准。

把失败任务原样再跑一次属于重试，不能称为系统已经自我改进。改进需要明确变更了提示、工具或评估标准，并在固定任务上比较成功率、耗时与成本；还需保留人工检查与回退边界。这补充了前述产物验收，而不替代验收。

## Dynamic Workflows：状态外置的适用边界

完整阅读 [AI超元域，2026-06-04，BV1a2EA6VEeX](https://www.bilibili.com/video/BV1a2EA6VEeX) P1全部298段字幕。视频中的代码图谱、跨工具演示未复现，性能宣称不入库为实测结论。当前 [Claude Code官方 Workflows 文档](https://code.claude.com/docs/en/workflows)（核验2026-11-08）说明脚本可维护规划和中间状态，适合复杂审计或迁移等工作。由此可以借鉴显式计划、持久化状态、停止条件；不能推出每次简短摘要都应增加多代理和跨工具桥接。

## 循环控制：图的步数与模型请求数不同（2026-11-09）

完整审阅[AI探索喵，2026-06-23，BV14Ejm6WE9s](https://www.bilibili.com/video/BV14Ejm6WE9s) P1全部187段字幕（0–358.82秒）；未看架构图。作者提出仲裁、共享状态、版本锁、预算与人工介入。可以保留的工程原则是：对共享写入与停止条件作显式约定，不能只依靠参与模型自行协调。

需纠正两个概念：有审阅返回重写的反馈环，就不再是DAG；精确哈希相等只说明内容完全相同，不能直接检测语义近似。[LangGraph Graph API文档](https://docs.langchain.com/oss/python/langgraph/graph-api)（核验2026-11-09，Graphs、Super-steps、Recursion limit章节）支持顺序、分支和循环；`recursion_limit`限制super-steps，多个并行节点可以共享一步。因此图步数、工具调用次数、模型请求次数与token消耗必须独立计量。

工程推断：预算应在模型请求发出前检查，重试也计入，并将已用额度持久化，防止进程重启后清零。共享状态还要规定写入归属、版本校验和提交规则；仲裁者或反思者仍可能误判，不能视作正确性保证。视频的十轮、三圈只是示例，未在本库验证为最优参数。

## 成功率口径：单次、至少一次与全部成功（2026-11-09）

完整审阅[AI探索喵，2026-10-09，BV1NEpt65EHf](https://www.bilibili.com/video/BV1NEpt65EHf) P1全部134段字幕（0.10–242.34秒），未看画面。作者先建议单次通过率，后又强调多次全通过；两种用途应区分，而不是用一个数字替代另一个。

| 指标 | 回答的问题 | 适用前提 |
|---|---|---|
| 单次通过率 | 一次交付能否成功 | 明确每次预算、任务分布和终态判据 |
| pass@k | k次中至少一次成功 | 产品允许重试及筛选，重试成本计入 |
| pass^k | k次全部成功 | 关注重复可靠性，记录试验独立性 |

[Anthropic，Demystifying evals，2026-01-09](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)区分上述后两项，并强调按产品需要选择与人工校准模型评分。若单一任务各次独立且成功概率均为p，至少一次成功为1−(1−p)^k，全部成功为p^k；p=0.7、k=3时后者为0.343。任务难度不同或试验相关时，不能直接把全体平均成功率代入幂次公式。

补充前文验收标准：记录任务终态、不可接受副作用、预算与返工，而非只验接口返回成功。换一个裁判模型不自动获得独立客观性，需要与人工标注核对误判。以上为指标设计与来源审阅，没有宣称做过可靠性重复实验。

## 失败反馈怎样改进提示词：APO 的边界（2026-11-11）

问题：得到失败样本后，怎样让提示词更新成为可检验的改进？

完整代读[Agent智能体深度研究院，2026-06-10，BV1sJEZ6nEWn](https://www.bilibili.com/video/BV1sJEZ6nEWn) P1全部207段字幕（0.04–529.26秒），未看画面。开头回顾2023年论文，中段解释候选选择，结尾强调外部文本更新后重新验证。编排层核对了[Pryzant等，EMNLP 2023：Automatic Prompt Optimization with “Gradient Descent” and Beam Search](https://aclanthology.org/2023.emnlp-main.494.pdf)的§2.1/2.2方法及§4学习曲线和定性讨论相关文字；不是论文全文审阅，未复核图表或复现实验。

1. **论文方法**：ProTeGi从失败样本产生自然语言批评，据此编辑提示词、扩展候选，用束搜索和bandit选择管理搜索与评估。优化对象是外部文本；“梯度”是类比，不更新模型权重。
2. **论文边界**：批评可能误诊，候选可能过拟合或改变任务。例如把通用越狱检测缩窄为某个话题检测，局部分数变好也不等于原任务改进。论文中的分类任务结果不能证明长程Agent、Skill或整个Harness会自动改善。
3. **工程推断**：先区分提示歧义、检索遗漏、工具失败等原因，再提出单一可回退修改；用未参与改写的案例验证，记录请求成本和回归。不能把更长反思或更多迭代当作进步。

这补充前文的改进循环与成功率口径。视频将APO关联到现代Skill/Harness，是解释性延伸；完整评估协议、数据隔离和本地重复试验仍待补，本次不引用性能提升数字。

## 代码图谱能证明什么：结构索引与运行证据（2026-11-11）

问题：代码图谱给出的调用关系、死代码与影响范围，能否直接用于改动决策？

完整代读[AI超元域，2026-06-22，BV1Ma7T6jEnu](https://www.bilibili.com/video/BV1Ma7T6jEnu) P1全部287段字幕（2.36–666.38秒）。开头介绍codebase-memory-mcp，中段对比CodeGraph，后段演示PR影响、死函数和迁移方案；未看评分表画面或复现代码。核验[DeusData项目README](https://github.com/DeusData/codebase-memory-mcp/blob/main/README.md)的介绍、安装、图分析及性能相关段落，2026-11-11读取的README blob为`8eebe8bd9c882cc33f3ec69e814937b2f801b127`；未完整审计源码，当前README也不代表视频旧版及作者改版。

1. **官方文档支持**：结构索引用于缩小源码阅读范围；静态调用路径不能证明实际运行，运行时trace属于另一类证据。先核对索引覆盖和新鲜度，再解释关系。
2. **修正视频主张**：“无已索引调用者”只能产生死代码候选。反射、注册表、动态分派、框架约定和覆盖缺口都可能产生反例，不能仅依图删除函数。“只含真实调用”也不能解释成已观察到运行。
3. **研究推断**：覆盖文件类型不同、节点边更多和模型主观评分不能证明准确率领先；迁移计划不等于迁移成功。应冻结仓库/工具版本，用相同问题和可核对的源码证据比较正确性、耗时与请求量，性能宣称留待复现。
