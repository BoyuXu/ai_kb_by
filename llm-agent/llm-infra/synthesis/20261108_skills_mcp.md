# Skills、渐进式披露与 MCP：视频观点的来源复核

核验：2026-11-08。视频：[AI探索喵《Agent架构中的Skill是什么？渐进式披露是如何实现的？》](https://www.bilibili.com/video/BV1FuJg62EQL)。覆盖：单P、5分26秒，读取返回的153段中文字幕，未逐帧核对图示。发布日期以B站元数据为准。

## 可保留的认识

Skill 可以把操作说明、参考资料和脚本组成一个能力包。渐进式披露先提供名称与用途，需要时加载完整说明，再按需读资源。官方 Agent Skills 文档支持这一流程；它降低常驻上下文负担，但不代表任务执行中没有上下文上限。[Agent Skills 概览](https://agentskills.io/home)

## 需要纠正的边界

| 视频说法或引申 | 入库后的准确表达 |
|---|---|
| MCP 将技能管理标准化，跨平台无缝切换 | Agent Skills 是以 `SKILL.md` 为核心的能力包格式；MCP 定义 AI 应用与外部工具、数据及工作流的连接。两者能配合，不能混称同一个标准。运行环境和客户端支持仍需检查。 |
| 挂成千上万技能后不再受上下文限制 | 按需加载减少驻留内容；目录大小、路由准确率、已加载材料仍受上下文与运行时约束。 |
| 必须有自动卸载机制 | 这是视频提出的工程方案，不能当作所有客户端的必备规范；具体如何清理需看宿主实现。 |
| 一定省钱且响应更快 | 视频没有提供受控实测；应同时测加载调用开销、缓存、首响应时间及端到端成功率。 |

前两项的规范边界可对照 [Skills 格式规范](https://agentskills.io/specification) 与 [MCP 官方介绍](https://modelcontextprotocol.io/docs/getting-started/intro)。后两项为本次审阅提出的验证要求，不是规范承诺。

## 一个可检验的工程问题

同一批知识整理任务，对比“整份手册始终加载”和“短目录＋按需读取”：记录完成率、来源错配、重复加载、总 token、耗时。若成本下降但漏读关键规则增多，不能只凭 token 数判断优化成功。
